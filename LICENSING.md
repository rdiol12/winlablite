# Licensing and resale policy

Goal: winlab stays **sellable as closed-source commercial software** while every
third-party component stays free and correctly licensed.

Not legal advice. The structural rules below are what the architecture enforces;
get a lawyer's sign-off before you take money.

## The one rule that makes this work

**winlab ships only its own code plus a downloader.** Anything that is GPL or
Microsoft-licensed is fetched by the end user, onto the end user's machine, at
first run. winlab never redistributes it.

That is why `winlab bootstrap` downloads QEMU from MSYS2 and the DSC resource
modules from the PowerShell Gallery instead of bundling them, and why no
Microsoft media is ever included. The MIT modules could legally be bundled;
fetching them keeps one rule for everything third-party.

## Your own product: activation, packs and updates

Nothing third-party is involved: the key format, the Ed25519 tokens and
update manifests (`winlab/licensing/`), the encrypted content pack
(`winlab/packs.py`, HMAC-SHA256 from Python's standard library) and the
release upload (`tools/upload_release.py`) are all winlab's own code.

* The website (`https://smartcartapp.net`, one constant in
  `winlab/licensing/client.py`) checks a key once, at activation, and signs a
  token for that key and PC. `VENDOR_PUBLIC_KEY_HEX` in
  `winlab/licensing/keys.py` must hold the site's public key before a
  release (`python -m winsite site-info` prints it).
* Every lab except the free trial lab ships inside
  `content/packs/labs-full.wlpack`, encrypted with the pack key the site hands
  only to activated PCs. Decrypted content is kept in memory, never written to
  disk.
* What this protects, honestly: seats, signed tokens and signed updates are
  real controls. File encryption on the customer's PC stops casual copying of
  the install folder; someone with a valid key can still extract what their
  own PC decrypts, and the Python code inside winlab.exe is readable by a
  determined person.

## Hard rules

1. **Never bundle, mirror, re-host or pre-install Microsoft ISOs, VHDs or
   product keys.** This is the only item on the list with real legal teeth.
   Microsoft eval media is free to download but not yours to distribute, and the
   eval terms forbid production use — fine for a lab, fatal if you ship it.
2. **Keep QEMU at arm's length.** winlab talks to it only by launching the
   executable and speaking QMP over a socket. No linking, no imported headers,
   no patched QEMU source in the tree. That keeps winlab a separate work rather
   than a GPL derivative, which is what lets you keep your own code closed.
3. **If you distribute the bootable appliance image**, that image is a GPL
   aggregate. Ship the license texts and a written offer for source for the GPL
   parts. Your orchestrator code stays separate and unaffected — mere
   aggregation on the same media is not a combined work.
4. **Do not strip upstream copyright or license notices** from anything fetched.

## What you are actually selling

Not a hypervisor, and not an operating system. You are selling the orchestration,
the network fabric design, the role library, the graded exercises and the
packaging — all original work. The free components are plumbing the customer
installs themselves.

This is the same posture Vagrant, Packer and dozens of commercial lab products
use, and it is well-trodden ground.
